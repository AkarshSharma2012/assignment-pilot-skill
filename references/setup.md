# First-run adaptation

Follow the Autopilot pattern: discover, verify, save a minimal profile, then explain how to use it. Do not require Autopilot to be installed.

1. Inspect applicable workspace instructions and existing assignment records. Inventory only relevant tools for connectors, supported browser control, local files, document rendering, code execution, and scheduling. Do not scan personal folders or credentials for possible accounts.
2. Resolve requested platforms and classes from user context or visible authorized sessions. Ask for missing school portal/course identifiers only when ambiguous. Let users perform credential entry and MFA through supported sign-in. Do not extract cookies or reverse-engineer tokens.
3. Prefer an exposed supported connector. Test class/assignment listing read-only and verify the account and class, then record each operation independently: list, read, download, attach, submit, grades. “Configured” is not “connected”; a listed platform is not proven compatible. Status values are `tested`, `untested`, `unavailable`, or `authorization-required`, with dated evidence and a limitation.
4. If no suitable connector, use the host's supported background browser tools and a dedicated session/group when supported. Follow that tool's documentation. If unavailable, offer manual exported instructions/files, or the scoped relay procedure. Never substitute hidden APIs or unsupported browser automation.
5. Resolve archive root, timezone, date naming convention, course scope, output preferences, and authorization mode. Modes: inspect, prepare, upload-only, or submit for explicitly selected scope. Default to inspect when authorization is absent. Do not silently inherit one student's settings for others.
6. Record private project state in `.assignment-pilot/` or the user's chosen private location outside the skill/repository. Include schema version, platform account alias (not credentials), course IDs, capability evidence, policy, holds, jobs, queue, and last notified events. Add private state to ignore rules before source control. If filesystem unavailable, label setup session-only. If using the helper, `python <skill>/scripts/assignment_pilot.py init --root <private-project>` creates a default-deny example only; populate live fields after verification.
7. Summarize the tested route, limitations, classes, permission mode, local folder, schedule status, and one next action. Give normal-language examples and explain that changing upload-only to submit needs explicit scope authorization. No automatic install, relay start, account grants, or billing changes during discovery.

On later runs check account, capabilities and policy freshness; refresh when tools, login, class scope, rubric, schedule or user instructions change. Support pause/cancel, individual holds, changing archives, manual review, and setup repair. Export configuration as a sanitized template with account aliases and empty IDs, not copies of private state. Importing a template never imports authorization.
